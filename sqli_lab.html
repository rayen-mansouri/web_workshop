Step 2 — your first real payload

Copy it. Paste it above. Watch the query break.

A payload is just text crafted to close the quote early. This one turns a single search box into a login bypass — no password ever checked.

' OR '1'='1' -- -
A single quote closes the string the backend opened for you. OR '1'='1' is always true, so the WHERE clause matches everything. -- - comments out whatever the backend was going to append after your input — the stray trailing quote never gets a chance to break the syntax.

The box below is a real, working mini backend — a tiny simulated users table it queries exactly the way the SQL above describes. If it logs you in as admin, that's not a trick: your text really did become part of the query.

1

2

3
OR '1'='1' is appended to the WHERE clause — it's always true, for every row.
4
-- - comments out the original trailing quote, so the query stays syntactically valid and runs.
Step 3 — same idea, different database

Payloads aren't one-size-fits-all

The logic above — "close the string, inject a true condition, comment out the rest" — is universal. But the exact syntax for comments, string concatenation, and reading internal data changes from one database engine to another. Using the wrong dialect is the #1 reason a working injection looks "blocked" when it isn't.

Comment syntax & quirks by engine
🐬MySQL / MariaDB
Comment: -- (needs trailing space) or #
Concat: CONCAT(a,b)
Schema: information_schema.tables
🐘PostgreSQL
Comment: -- (no space needed)
Concat: a || b
Schema: information_schema.tables
🪟MS SQL Server
Comment: --
Concat: a + b
Schema: sys.tables, stacked queries allowed
🔶Oracle
Comment: --
Concat: a || b
Schema: ALL_TABLES, every SELECT needs FROM dual
🪶SQLite
Comment: --
Concat: a || b
Schema: sqlite_master, no stacked queries via most drivers

That's also why attackers fingerprint the database first — usually by seeing which error message or which comment style makes the query behave as expected — before picking the rest of their payloads.

Step 4 — pulling data out with UNION

From "always true" to "show me everything"

Bypassing a login proves the injection works. UNION SELECT is how attackers go further — appending a second, attacker-chosen query whose results get merged into the page's normal output. It only needs the same number of columns as the original query.

Where your text can land in a query

Step 5 (bonus) — reading files and running commands

When the database can touch the server itself

Some engines ship functions that go past the data in the tables and reach the filesystem or the operating system directly. If the database account has the privilege, SQL injection stops being "leak a table" and becomes "read any file" or "run any command" on the server. Step 6 — why this is a big deal

It's never just "one extra row"

A bypassed login proves the query ran. In a real attack, the same flaw usually means every row, in every table, is readable — and on a misconfigured server, the database account's filesystem or command privileges turn into a full foothold on the machine.
